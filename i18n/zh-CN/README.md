## 1. 一句话定位

**人的注意力放在业务目标和最终效果上；智能体与大模型在受治理、可验证的交付系统内完成工程工作。**

这套方法论给出的是：跨会话的项目记忆、改动前先加载的规则、老项目先探明再动手的纪律、任务路由与可执行批次、可复用 Skill 与标准模板、后端掌握真相与前端只做展示的边界、宣布“完成”之前的验证门禁，以及把重复犯错变成更强规则/测试/Skill 的进化闭环。

## 4. 中文版与英文正式源的关系

1. **英文源是唯一正式源（source of truth）**。中文版是叠加的对照层，不替代、不覆盖、不修改英文源。
2. 中英表述冲突时，**以英文源为准**，并在 `90_校验/` 记录待修条目。
3. 同步规则见 [`00_导读/03_翻译口径与同步规则.md`](00_导读/03_翻译口径与同步规则.md)：每篇译文头部都标注了「源文件 / 源版本」，英文源更新后按源文件定位、只改受影响章节。
4. 本册**不是**一个可执行的 Runtime。规则的可执行化（`Rule Runtime Lite`）仍是源仓库的未来方向，本册不新增任何运行能力。

## 5. 为什么不是“把英文换成中文”

| 约束 | 证据 | 后果 |
|---|---|---|
| 审计脚本有 FAIL 级英文断言 | `scripts/py/audit_methodology.py` 要求 `scope/specify/ship/safeguard/sell`、`l0`–`l3`、`q0`–`q3`、`qualification`、`saleability`、`product owner`、`command gateway`、`ui atom`、`host page`、`fresh evidence`、`two independent axes` 等 | 纯中文替换 → 方法论审计 FAIL |
| 反模式扫描器是中文正则 | `scripts/py/audit_skill_health.py` 的 `ANTI_PATTERNS` | 中文正文里写「前端不得计算金额」会被误判为鼓励前端业务逻辑 |
| 规则扫描器检查盘符路径与根目录散文件 | `scripts/py/rule_lint.py` | 中文示例里出现本机盘符路径即 FAIL |
| 章程检查已同时接受中英术语 | `scripts/py/check_constitution.py` | 仓库本身为双语治理留了口子 |

因此本册的策略是：**中文负责“人读得懂”，英文负责“机器认得出”**。术语表第 12 节《禁译清单》明确了哪些必须保持英文。

## 6. 边界与非主张

- 不承诺 AI 无条件替代产品负责人或业务负责人。人仍然负责业务意图、优先级、重大取舍、风险接受和最终业务验收。
- 不提供通用 Runtime、调度器或命令执行沙箱；本册是文档与方法论，运行能力由采用它的项目自己实现。
- 中文版不改变任何规则的效力范围：门禁、非目标、破坏性操作确认等约束在中文版里同样成立，表述强度（必须/禁止/应当/可以）与英文源一致。
