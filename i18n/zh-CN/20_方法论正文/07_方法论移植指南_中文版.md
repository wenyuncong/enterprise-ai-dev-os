## 1 概述 | Overview

本指南说明如何**为任何项目自举（bootstrap）本方法论**——新项目或已有项目、任意技术栈、任意领域。

本方法论是一套**零依赖的文件系统**，不是 SaaS 产品。你复制文件夹、选择 Skill，AI 工具在会话启动时读取它们。无需安装、无需 API key、无需运行时（runtime）。

## 3 新项目快速开始 | Quick Start: New Project

### Step 0 分类项目 | Classify Your Project

在复制任何文件之前，先完成分类：

1. 判定：老项目（brownfield）还是新项目（greenfield）？
2. 判定：快速原型（Rapid Prototype）、AI 原生（AI-Native），还是企业级（Enterprise）？
3. 判定：仅 Web、Web+Mobile、Web+WeChat，还是全平台（All platforms）？
4. 判定：单体（Monolith）、原子服务（Atomic Services），还是微服务（Microservices）？

该分类决定复制哪些 Skill、套用哪种架构。完整决策框架见 `ai-project-classifier`。

---

### Step 0b 搭建项目文件夹 | Scaffold Project Folders

完成分类后，按你的原型（archetype）创建对应的文件夹结构：

**原型 A（Archetype A，Rapid Prototype）**：

```
mkdir backend frontend database docs scripts skills rules
```

**原型 B（Archetype B，AI-Native）**：

```
mkdir backend/services backend/gateway backend/common
mkdir frontend/web frontend/shared
mkdir database/migrations database/seed database/schema database/backup
mkdir docs/_templates docs/架构决策记录 docs/每日调研回写 docs/业务流程全案 docs/测试验收报告 docs/部署运维手册 docs/全项目总控
mkdir scripts/bat scripts/ps1 scripts/py scripts/js scripts/ci
mkdir config docker/dev docker/prod
mkdir skills/core skills/governance skills/tech
```

**原型 C（Archetype C，Enterprise）**：原型 B + `mobile/` + `wechat/` + `mcp-server/` + `docker/staging/`

完整搭建标准：methodology/08_项目文件夹结构标准.md

### Step 1 复制核心 | Copy the Core

```bash
# 从方法论仓库复制到你的项目根目录：
cp rules/AGENTS.md {your-project}/
cp -r skills/core/ {your-project}/skills/
cp -r skills/governance/ {your-project}/skills/
```

### Step 2 选择技术栈 Skill | Select Tech Skills

```bash
# 只挑选与你技术栈匹配的 Skill：
# 前端：
cp -r skills/tech/vue/ {your-project}/skills/       # 若使用 Vue
cp -r skills/tech/vue-best-practices/ {your-project}/skills/
# 或者
# cp -r skills/tech/react-frontend/ {your-project}/skills/  # 若使用 React

# 后端：
cp -r skills/tech/java-springboot/ {your-project}/skills/   # 若使用 Spring Boot
cp -r skills/tech/springboot-patterns/ {your-project}/skills/
# 或者
# cp -r skills/tech/node-backend/ {your-project}/skills/    # 若使用 Node.js

# 数据库：
cp -r skills/tech/mysql-best-practices/ {your-project}/skills/

# Docker：
cp -r skills/tech/docker-expert/ {your-project}/skills/
cp -r skills/tech/multi-stage-dockerfile/ {your-project}/skills/
```

### Step 3 初始化文档 | Initialize Documentation

```bash
cp -r docs/_templates/ {your-project}/docs/
```

### Step 4 首次 AI 会话 | First AI Session

```
打开你的 AI 编码工具并输入：
"Read rules/AGENTS.md, then run ai-rule-dispatcher to audit this project and recommend next steps."

AI 将会：
1. 读取全部相关规则
2. 分析你的项目结构
3. 识别缺失的 Skill
4. 生成初始任务计划
5. 创建第一批文档条目
```

## 4 已有项目迁移 | Migration: Existing Project

### Phase 1 审计（第 1 天）| Audit (Day 1)

1. 复制 `rules/AGENTS.md` 到项目根目录
2. 运行 `ai-rule-dispatcher` 做全项目审计
3. AI 将产出差距分析报告：
   - 哪些方法论规则已被遵守？
   - 哪些缺失？
   - 引入方法论变更的风险是什么？

### Phase 2 核心 Skill（第 1 周）| Core Skills (Week 1)

1. 复制 `skills/core/` 到项目
2. 开始用 `ai-rule-dispatcher` 做任务路由（低风险——它只给建议，不改代码）
3. 开始用 `ai-task-decomposer` 处理新的复杂任务（不影响既有代码）
4. 开始在 `docs/每日调研回写/` 下写每日回写

### Phase 3 治理（第 2 周）| Governance (Week 2)

1. 复制 `skills/governance/` 到项目
2. 对一个关键模块运行 `ai-flow-closure-audit`
3. 对一组关键页面运行 `ai-frontend-audit`
4. 逐条增量处置发现项

### Phase 4 全量采用（第 3 周及以后）| Full Adoption (Week 3+)

1. 所有新开发强制走 13 步顺序
2. 启用 `ai-skill-evolver` 做持续改进
3. 集成部署门禁
4. 培训团队成员掌握方法论用法

## 5 定制化 | Customization

### 新增一个技术栈 Skill | Adding a New Tech Skill

```bash
# 创建 Skill 目录
mkdir -p {your-project}/skills/tech/{your-stack}

# 按此模板撰写 SKILL.md：
#   - Purpose（目的）
#   - Core Rule（核心规则）
#   - When to Use（何时使用）
#   - Standard Workflow（标准工作流）
#   - Guardrails（防护规则）
#   - Project-Specific Notes（项目专属说明，你自定义的规则写在这里）
```

### 修改核心方法论规则 | Modifying Core Methodology Rules

1. 禁止直接修改 `skills/core/` 下的 Skill——它们是权威版本（canonical versions）
2. 改为在 `rules/project_rules.md` 中创建项目专属覆盖（overrides）
3. 项目规则优先于核心规则

### 新增领域专属治理 Skill | Adding Domain-Specific Governance Skills

1. 在 `skills/governance/` 下新建 Skill
2. 审计类 Skill 命名格式为 `ai-{domain}-audit`
3. 遵循治理 Skill 模板（purpose → core rule → workflow → guardrails）

## 7 常见问题 | Troubleshooting

| 问题 | 解决方案 |
|---|---|
| “AI 忽略规则” | 确认 `rules/AGENTS.md` 位于项目根目录且触发配置（trigger config）正确 |
| “Skill 之间互相冲突” | 运行 `ai-rule-dispatcher`——它会选出且只选出一个主导 Skill（lead skill） |
| “文档膨胀过快” | 只回写会影响后续 AI 会话的发现；琐碎笔记直接跳过 |
| “Skill 已过时” | 运行 `ai-skill-evolver`——它会检测并修复腐化（rot） |
| “团队不知道怎么用” | 让每位团队成员先跑一次会话，输入 “Read rules/AGENTS.md” |
