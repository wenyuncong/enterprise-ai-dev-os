## 1. 为什么需要发布治理？| Why Release Governance?

Step 13（Runtime Verify，运行时验证）证明页面能渲染。但它证明不了：
- 所有业务流程端到端都能走通
- 所有 P0 缺陷都已修复
- 所有功能都真的完成了（而不只是"代码写完了"）
- 版本边界清晰（什么在内，什么在外）
- 关键路径上已经做过人工测试

GERP 的发布闭环体系抓住了自动化检查漏掉的问题。本篇方法论把这个模式固化下来。

## 4. 缺陷分级 | P0/P1/P2 Bug Classification

### P0 — 发布阻断（Blocks Release）
**发布前必须清零。**

| 判定标准 | 示例 |
|---|---|
| 核心业务流程中断 | 无法创建采购订单 |
| 数据丢失或损坏 | 事务删除了错误的记录 |
| 安全漏洞 | 未认证即可访问 API |
| 租户隔离被击穿 | 租户 A 看到租户 B 的数据 |
| 支付/计费错误 | 扣款金额错误 |

### P1 — 必须修复（Must Fix）
**发布时允许 < 5 个。每一个都要记录规避方案。**

| 判定标准 | 示例 |
|---|---|
| 重要功能损坏 | 导出超过 1000 行时失败 |
| 阻塞式体验问题 | 移动端模态框无法关闭 |
| 性能退化 | 页面加载 > 10 秒 |
| 数据展示错误 | 报表显示错误的合计 |

### P2 — 建议修复（Nice to Fix）
**可以带着 P2 缺陷发布。记录在已知问题中。**

| 判定标准 | 示例 |
|---|---|
| 外观问题 | 某个页面按钮未对齐 |
| 边界情况 | 姓名中的特殊字符导致显示异常 |
| 优化项 | 页面加载时存在冗余 API 调用 |

## 5. 人工测试台账 | Manual Test Ledger

自动化测试无法验证一切。关键路径需要人眼确认。

### 模板 | Template
```markdown
## 人工测试台账

| # | 测试场景 | 模块 | 操作步骤 | 预期结果 | 实际结果 | 测试人 | 日期 |
|---|---|---|---|---|---|---|---|
| 1 | 创建采购订单-完整流程 | 采购 | 新建→添加行→保存→提交→审批 | 状态流转正确 | ✅ | | |
| 2 | 库存入库-批次管理 | 仓库 | 收货→质检→上架 | 库存更新正确 | ⚠️ 批次号未自动生成 | | |
```

## 6. 业务流程验收矩阵 | Business Process Acceptance Matrix

每条关键业务流程都必须端到端验证。

### 模板 | Template
```markdown
## 业务流程验收矩阵

| 流程 | 模块 | Page→API→DB→Writeback | 自动测试 | 人工验证 | 状态 |
|---|---|---|---|---|---|
| 采购订单→入库→付款 | 采购+仓库+资金 | ✅ | ✅ | ✅ | PASS |
| 销售订单→出库→收款 | 销售+仓库+资金 | ✅ | ✅ | ⚠️ | P1: 收款未自动核销 |
| 生产工单→领料→完工 | 生产+仓库 | ✅ | ❌ | — | BLOCKED: 无测试 |
```

## 7. 多对话协作 | Multi-Conversation Coordination

GERP 的发布闭环涉及多个 AI 对话和人工测试人员。协作规则如下：

### 规则 | Rules
1. **一份总控文档** —— 发布状态的唯一真相源
2. **对话命名**：`{date}_{role}_{task}` —— 例如 `2026-06-12_tester_regression`
3. **禁止静默覆盖** —— 如果两个对话改了同一个文件，必须标记出来
4. **每日同步** —— 每个对话在当天结束前把状态更新到总控台
5. **锁版协议** —— 一旦锁版，只允许修 P0；所有改动都需要审批

## 8. 与 13 步集成 | Integration with 13-Step Methodology

```
Step 12: Schema Sync（Schema 同步）
Step 13: Runtime Verify（运行时验证）
    │
    ▼
Step 13a: Release Governance（发布治理，新增——面向企业级发布）
    │
    ├── 在 docs/发布闭环/ 下创建发布文件夹
    ├── 填写锁版总控台
    ├── 执行 P0/P1/P2 缺陷审计
    ├── 执行人工测试台账
    ├── 验证业务流程验收矩阵
    └── 门禁：所有 P0 = 0，P1 < 5，人工测试通过
    │
    ▼
RELEASE
```

**规则**：Step 13a 对企业级（原型 C）发布是**强制**的。对 AI 原生（原型 B）发布可选。快速原型（原型 A）跳过。
