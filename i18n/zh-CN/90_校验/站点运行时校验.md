## 3. 逐页扫描的判定口径

对每一篇文档在浏览器里逐一打开，检查四项：

1. **一级标题必须存在** —— 防止渲染失败导致白页；
2. **渲染完整度 = 渲染后可见文本长度 / Markdown 原文长度 ≥ 0.55** —— 防止大段内容被渲染器吞掉（正常值在 0.85–0.95，因为标记符号被剥离）；
3. **横向溢出 ≤ 12px** —— 防止宽表格把版面撑破；
4. **有英文源的文档，英文侧同样校验完整度** —— 保证「对照」不是空的。

本次扫描全部通过，说明站点的中英两侧都不是「壳子」，而是真实渲染出了全部内容。

## 4. 站点是怎么做到“双击即用”的

- `site/index.html` 是**自包含单文件**：样式、脚本、以及全部 123 篇文档的中文与英文正文，全部在构建时内联进同一个 HTML。
- 因此它**不需要服务器、不需要联网、不需要 Node**；`file://` 直接打开即可，浏览器不会触发任何跨域限制。
- 「并排对照」的英文列取自每篇中文译文头部声明的 `源文件` 字段，所以中文版和英文源**永远指向同一份文件**，不会出现“对照错了源”的情况。头部若写成 `skills/tech/{a,b,c}/SKILL.md` 这种花括号展开式，构建器会先展开成具体路径再取源文件。
- **同步状态**由 `90_校验/source_hash_baseline.txt`（翻译开工时的源文件哈希，含一处已记录的基线重签发）与源文件**当前哈希**比对得出：一致显示「已同步」；不一致显示「源已变更，待重同步」；源文件不存在显示「源缺失」；本版新增显示「新增」。当前：已同步 114 篇、源已变更 0 篇、本版新增 9 篇。
- **在线发布**：站点产物不入库（已在 `.gitignore` 中忽略），由 `.github/workflows/pages.yml` 在 `i18n/zh-CN/**` 变更时用 `py site/build_site.py --source-root .` 构建，并复制到 `site/zh-CN/` 随 Pages 一起发布；本地预览走 `打开网站.cmd`（首次会自动构建）。

## 5. 如何重新生成与复校

```powershell
# 0. 提交前预检：确认中文版不会让主仓库的 check_portability 变红（复用主仓库的规则常量）
py 90_校验/check_repo_compat.py --source-root "<英文方法论仓库路径>"

# 1. 重新生成站点（内容有更新时执行；也可用 --source-root 指定英文源仓库）
py site/build_site.py --source-root "<英文方法论仓库路径>"

# 2. 复校（需要本机有 playwright；PLAYWRIGHT_ROOT 指向含 node_modules 的目录）
$env:PLAYWRIGHT_ROOT = "<含 node_modules 的目录>"
node 90_校验/verify_site_runtime.mjs --site site/index.html --shots 90_校验/screenshots `
     --json 90_校验/site_runtime_verify.json

# 3. 顺带校验整册（含站点门禁）
py 90_校验/verify_cn_edition.py --source-root "<英文方法论仓库路径>"
```

若本机 Playwright 的浏览器版本与缓存不匹配，脚本会自动依次尝试 **msedge 通道 → 缓存 chromium → 默认 chromium**，无需手动下载浏览器。

## 6. 本轮修掉的一个真实渲染缺陷（记录在案）

首次校验时 12/13，失败项是「正文内的站内链接可跳转」。原因是渲染器把行内代码（反引号）先于链接解析，遇到 `` [`路径`](路径) `` 这种**链接文字里含反引号**的写法时，方括号与圆括号被拆散，链接渲染不出来。修复方式是把链接与行内代码放在同一个扫描器里、并允许链接文字内部再解析行内代码。修复后 13/13 → 最终 12/12（检查项合并后计数）全绿。
