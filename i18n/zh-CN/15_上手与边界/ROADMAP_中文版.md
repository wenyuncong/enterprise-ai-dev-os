本路线图保持公开项目聚焦：Enterprise AI Development OS 是面向 AI 辅助开发的治理与适配层，不是通用 AI 应用平台。

## 定位 | Positioning

**当前 Open-Core Methodology 范围：**

- 完整的可移植规则与会话入口
- 完整的正式 Skill 体系、任务路由与执行纪律
- 方法论正文、标准、Schema 与文档模板
- 审计门禁、场景回归与就绪度评分
- 一键安装与 CLI 支持
- 面向 AI 编码工具的多工具适配器
- GitHub Pages 与社区协作文件

本仓库公开完整、可复用的方法论内核。真实项目源码、客户或租户数据、生产配置、私有策略，以及未脱敏的交付证据保持私有。

**未来高级能力范围：**

- 可执行的规则运行时
- 规则命中与失败报告
- AI 生成质量基准
- MCP / 工具调用审计模型
- 团队治理与策略包

高级能力范围刻意只作为未来工作描述。公开表述禁止暗示这些能力已经实现。

## 近期 | Near Term

| 事项 | 结果 | 公开状态 |
|---|---|---|
| 更清晰的价值主张 | 说明本项目让 AI 编码工具遵循项目规则与验证门禁 | 进行中（In progress） |
| 一键安装 | 用 `lite`/`full` 安装器降低引入门槛 | 已完成（Done） |
| 价值证据模板 | 跟踪 token、返工、缺陷、验证与一致性数据 | 计划中（Planned） |
| Rule Runtime Lite 设计 | 定义值得构建的最小可执行规则引擎 | 计划中（Planned） |
| GitHub 社区工作流 | Issues、PR、安全、治理、贡献流程 | 已完成（Done） |

## 下一阶段 | Next

| 事项 | 结果 | 备注 |
|---|---|---|
| 基准示例 | 小型、可复现的前后对比案例 | 只使用脱敏示例 |
| 规则包元数据 | 在做完整引擎之前，先用结构化文件描述规则 | 避免大型平台重写 |
| 工具兼容性证据 | 记录哪些适配器已验证、实验性、或待定 | 以 `tools/adapters.json` 为准 |
| 运行时验证证据 | 让验证输出在不同工具之间更易比较 | 不发布私有项目日志 |

## 后续 | Later

| 事项 | 结果 | 约束 |
|---|---|---|
| Rule Runtime Lite 实现 | 针对生成产物执行一小批规则 | 先做文件/路径/Schema 检查，再做 AST |
| AST / Tree-sitter 规则 | 为选定语言增加语义检查 | 仅在基准需求被证明之后 |
| MCP 审计模型 | 定义工具调用权限与审计记录 | 先做文档/规格，再做网关实现 |
| VS Code 扩展 | 可视化规则反馈与安装助手 | 仅在出现社区需求时 |
| 团队治理包 | 基于角色的规则包与审批门禁 | 业务相关内容保持私有 |

## 暂不做 | Out Of Scope For Now

- 区块链审计存储
- 物理门禁集成
- Kubernetes / GPU 调度器
- 完整模型生命周期管理平台
- 大型 Web 管理控制台

这些听起来也许很「企业级」，但会偏离当前价值：让 AI 编码在真实项目里更可预测地工作。
