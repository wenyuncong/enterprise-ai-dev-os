# 项目接入与技能供应链治理

## 决策

新增 `ai-project-onboarding-and-skill-integration`，将方法论接入固定为：

```text
Detect -> Discover -> Evaluate -> Plan -> Stage -> Merge -> Govern -> Index -> Verify
```

外部 GitHub 内容必须先进入 `skills/candidates/`；未记录来源、固定提交、
许可证和兼容性决策的候选不得启用。候选/隔离内容不属于可调用正式技能。

## 交付内容

- `scripts/py/project_onboarding.py`
  - `inspect`：受限扫描的语言、框架、数据库、包管理器、技能盘点与知识索引。
  - `preflight`：逐文件 `add/same/conflict` 方法论复制计划，不写目标项目。
  - `stage-github`：仅以显式 GitHub 仓库和 ref 进入候选区，并写来源锁。
  - `govern-candidates`：检查来源锁、固定提交、许可证、SKILL frontmatter。
- `skills/core/ai-project-onboarding-and-skill-integration/SKILL.md`
  - 定义项目私有、候选、隔离与正式技能的边界和启用条件。
- 项目接入记录与交付契约模板。
- 方法论审计和场景回归：缺少接入资产必须失败。

## 约束

知识索引仅用于发现与定位；它不能替代运行时权限、数据库事实、命令覆盖或
业务闭环证据。首次使用受限全量扫描，后续应基于源码、依赖、技能或脚本的
实质变更做增量刷新。
