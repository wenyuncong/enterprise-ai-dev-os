# GERP 全 AI 交付：安全修改、精准定位与重大项目自动驾驶

日期：2026-07-28

## 结论

GERP 的全 AI 开发不是让产品负责人学习代码，而是把人的职责稳定在产品结果、呈现效果、易用性、优先级和业务流程验收；把代码定位、架构判断、实现、验证、版本和发布交给受规则约束的智能体。

## 安全修改

1. 默认先读、先证明、后修改：先确定业务症状、唯一真相、候选文件、影响边界、验证与回退方式。
2. 删除和破坏性操作分级：可再生临时文件可证明后删除；任务专属源码先查引用和回退；共享或未知源码默认保留；数据库、配置、租户数据和破坏性 Git 命令必须由产品负责人明确确认。
3. 脏工作树不做全库清理：只暂存本任务文件或精确代码块，检查暂存差异后才提交，不吸收其他任务的修改。

## 精准代码定位

智能体按“业务现象 -> 菜单/路由 -> 实际 Host 页面 -> 共享模板与组件 -> 前端 API -> Controller/适配器 -> 命令网关/聚合接口 -> 编排/原子服务 -> FieldPackage、BusinessProfile、权限和数据库 -> 测试与发布门禁”追踪。

修复前输出候选文件、证据、修复归属、影响面和验证路径；产品负责人无需猜测文件或类名。

## 重大项目自动驾驶

重大项目按“定义结果 -> 映射现状 -> 分批 -> 实现 -> 证明 -> 面向产品的汇报 -> 发布或迭代”循环推进。每批选择 L0-L3 比例化验证，并只在业务规则不明确、重大范围取舍、不可逆操作或发布授权时请产品负责人决策。
