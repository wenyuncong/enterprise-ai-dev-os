# Public Disclosure Boundary

## 1. 默认原则

本项目采用 **Open-Core Methodology** 边界：

- 完整、可迁移、可复用的方法论内核公开；
- 真实项目交付资产、客户信息、运行数据和商业策略保持私有；
- “方法论完整开源”不等于“项目过程和生产资料全部公开”。

任何未明确进入公开包的资料，都默认视为私有资料。

| 等级 | 是否可外发 | 说明 |
|---|---|---|---|
| Public | 可以 | 已脱敏、可开源、可发客户 |
| Private | 不可以 | 私有策略、过程记录、未脱敏案例、本地素材 |
| Generated | 需复核 | 工具输出、验证证据、适配目录、缓存文件 |

没有明确标为公开的内容，不得默认外发。

## 2. 完整开源的方法论内核

以下内容可以作为公开仓库的正式产品表面：

- 完整方法论白皮书、标准和规则；
- 全量官方 Skill、Skill manifest 和通用参考资料；
- 可复用的任务、交付契约、迁移门禁、租户回归和架构模板；
- Schema、审计器、验证脚本、CLI、安装器和适配器生成器；
- Lite 包、GitHub Pages 网站、兼容矩阵和社区协作文件；
- 已去标识化、可迁移的通用案例、反模式和验证场景。

公开内容应满足：不依赖特定客户、租户、部署环境、本机路径、账号、密钥或未公开商业决策。

## 3. 不能开源或外发的内容

- 私有策略材料
- 过程记录和未整理证据
- 未脱敏客户、项目、部署、账号或联系方式
- 本机绝对路径和个人环境配置
- 未脱敏案例
- 未审计的工具输出、截图、日志、缓存
- 可复用前还没有泛化的专属实现细节

## 4. 可公开但需复核的内容

- 真实项目提炼出的案例：必须去标识化并删除专属业务规则；
- 工具输出、截图、日志和测试证据：必须删除本机环境、客户数据和敏感信息；
- 量化收益、性能和商业结果：必须有可复核的公开证据；
- 新增适配器：必须完成规则加载、Skill 加载和运行行为验证。

## 5. 对外材料生成流程

1. 从私有材料提炼摘要。
2. 删除客户、项目、部署、账号、路径和策略动作。
3. 改写为公开语言。
4. 放入 `docs/公开材料/`。
5. 运行审计或人工复核。
6. 再用于开源、客户沟通或路演。

## 6. 当前结论

公开仓库发布完整的产品化方法论内核及其可执行工具链；私有策略、过程记录、真实交付证据、客户/租户资料和未脱敏案例不进入公开范围。
